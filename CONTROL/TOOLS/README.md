# Команды пульта

Одинаковые для любого агента: агент вызывает команду — результат один и тот же, кто бы ни управлял.
Готова `publish` (вместе с `archive`) — `publish.py`, остальные пока описаны.

| Команда | Что делает |
|---|---|
| `queue` | показать очередь READY по всем проектам и сетям |
| `prepare` | собрать пост в READY из TEXT + PHOTO/VIDEO на нужную дату и время |
| `check` | проверить пост: лимиты сети, ссылка, уникальность против READY и PUBLISHED всех сетей |
| `publish` | **готово:** `publish.py` — публикует посты из READY, время которых наступило, переносит в PUBLISHED + `info.json`; каждый час через GitHub Actions (`publish.yml`); `--check` доступы, `--due --dry-run` план, `--post <папка>` один пост; адаптеры сетей — `net_<сеть>.py` (Instagram, Facebook, Threads, Telegram); `--test TELEGRAM` — пробный пост в личку; стоп-кран `CONTROL/PUBLISHING.yaml` (`pause_except` — сети, которые выходят и на паузе; `pause_allow` — список папок утверждённых постов в READY, которые выходят и на паузе) |
| `archive` | **готово внутри `publish`:** вышедший пост → PUBLISHED/ГГГГ-ММ/ + info.json (дата, время, ссылка) |
| `image-request` | заявка на картинку Higgsfield (генерация — только после согласия пользователя на цену) |

## Готовые инструменты для картинок (10.10.2026)

Правила — `CONTROL/IMAGE-RULES.md`. Нужны Python 3, Pillow, cairosvg (для SVG), curl.

| Скрипт | Что делает |
|---|---|
| `logo_badge.py <картинка> [логотипы…] -o <файл.jpg>` | логотип бренда белой плашкой внизу слева; приводит картинку к формату хранения (JPG, до 1600 px); `--side --quality --max-kb` — для каналов со своими требованиями (блог OSTAPDOTCENKO) |
| `save_images.py <список.json>` | скачивает сгенерированные картинки, накладывает логотипы, кладёт в `PHOTO/` под именем текста, пишет поля `image*` в шапку текста; новые логотипы — в `CONTROL/LOGOS/` с источником |
| `contact_sheet.py <ПРОЕКТ/СЕТЬ> <с №> <по №> -o <лист.jpg>` | лист картинок на согласование: номер, дата, время, заголовок, статус |
- `carousel_import.py <ПРОЕКТ> <номер> <имя>` — готовая карусель из VIDEO-HUB → `<ПРОЕКТ>/INSTAGRAM/CAROUSEL/PHOTO/<NN>_<тема>/01.jpg…` + `TEXT/<NN>_<тема>.md`; если карусель уже в расписании — обновляет те же файлы (дата и связка остаются). Подпись под постом собирается из всех слайдов (обложка, цифра, маршрут, «что вы поймёте», «почему с нами», «что входит», «для кого», призыв, хештеги темы и страны + проекта, до 2200 знаков). `carousel_import.py GTT --captions` — пересобрать подписи всех каруселей (правленные руками не трогает).
- `instagram_plan.py <ПРОЕКТ> [--apply] [--html файл]` — раскладка Instagram по `<ПРОЕКТ>/INSTAGRAM/PLAN.json` (первый запуск, ритм недели, темы недель, очереди каруселей, праздники): без ключей — показать календарь; `--apply` — даты в именах (`git mv`), тексты Reels и Stories, Stories-анонсы (рендер в VIDEO-HUB, `npm run announce`), `КАЛЕНДАРЬ.md`; `--html` — календарь с картинками для показа пользователю. Новый ролик или карусель → дописать в `PLAN.json` и запустить `--apply`.
- `to_ready.py` — переносит утверждённые посты (все `status` / `image_status` / `caption_status` = «утверждено») из запаса в очередь; Instagram: папки слайдов карусели и сторис, Reels и сторис из роликов без файлов (видео по `video_hub`), копия картинок в публичный VIDEO-HUB `finished-videos/publish/` и ссылки `media_urls` в шапке (`--only <имя>` — один пост); раньше — только текст + картинка: `READY/<дата_время_тема>/` (`post.md` + `photo.jpg`), только через `git mv`; `--dry-run` — показать, что будет перенесено. Блог: `to_ready.py <ПРОЕКТ>/BLOG --time 15:00` — языковые файлы статьи едут в одну папку как `post.ru.md`, `post.en.md`, `post.zh.md` + `photo.jpg`, в шапку пишется `publish_time`.
