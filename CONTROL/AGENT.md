# AGENT.md — единая инструкция для любого агента POST-HUB

Этот файл читает любой агент, который управляет репозиторием: Claude, ChatGPT (Codex) или другой.
Входы `CLAUDE.md` и `AGENTS.md` в корне ведут сюда. Общайся с пользователем по-русски.

## 1. Кто сейчас управляет (проверять первым делом)

Открой `CONTROL/ACTIVE-AGENT.yaml`.

- Если в поле `agent` указан ты — работай.
- Если указан другой агент или `none` — **ничего не меняй в репозитории**: только читай и отвечай пользователю,
  что управление сейчас у другого агента. Переключает пользователь кнопкой
  (GitHub → Actions → «Переключить агента» → Run workflow).

## 2. Что здесь лежит

Три проекта — три отдельных сайта со своим уникальным контентом и своими каналами:

| Папка | Проект |
|---|---|
| `AURA/` | Aura Robotics — aura-robotics.ru |
| `GTT/` | GlobalTechTour — globaltechtour.ru |
| `OSTAPDOTCENKO/` | личный сайт и каналы |

В каждом проекте 11 сетей: `TELEGRAM`, `DZEN`, `BLOG`, `FACEBOOK`, `LINKEDIN`, `INSTAGRAM`, `THREADS`, `X`,
`YOUTUBE`, `WECHAT`, `XIAOHONGSHU`. Четыре сети разделены на форматы — у каждого формата своя очередь:

| Сеть | Форматы |
|---|---|
| `INSTAGRAM` | `POST` (одно фото/видео), `CAROUSEL` (слайды), `REELS`, `STORIES` |
| `FACEBOOK` | `POST` (фото, видео, текст, несколько фото), `REELS`, `STORIES` |
| `YOUTUBE` | `LONG` (обычные ролики), `SHORTS` |
| `DZEN` | `ARTICLE` (статьи), `POST` (короткие посты), `LONG` (видео), `SHORTS` (ролики) |

Путь к контенту: `<ПРОЕКТ>/<СЕТЬ>/<ПАПКА>` или, если у сети есть форматы, `<ПРОЕКТ>/<СЕТЬ>/<ФОРМАТ>/<ПАПКА>`.
Папки везде одинаковые:

| Папка | Что в ней |
|---|---|
| `TEXT/` | запас текстов |
| `PHOTO/` | запас фото (сгенерированные и от пользователя) |
| `VIDEO/` | запас видео |
| `READY/` | очередь: готовые посты по дням, папка на пост — текст + фото или видео |
| `PUBLISHED/` | архив вышедшего по месяцам, с датой и временем публикации и ссылкой на пост |

`RULES.md` лежит на уровне сети (с разделом «Форматы») и на уровне проекта.

Кроме сетей, в каждом проекте:

| Путь | Что в нём |
|---|---|
| `<ПРОЕКТ>/RULES.md` | правила проекта: о проекте, аудитория, тон, темы, факты, ссылки, связь сетей |
| `<ПРОЕКТ>/VIDEO.md` | стиль роликов проекта (шаблон, эффекты, логотип в кадре) |
| `<ПРОЕКТ>/BRAND/BRAND.md` | брендбук: палитра, шрифты, формы, правила фото |
| `<ПРОЕКТ>/BRAND/LOGO/` | логотипы и кадры живого логотипа |
| `<ПРОЕКТ>/BRAND/FONTS/` | файлы шрифтов (лицензия OFL) |
| `<ПРОЕКТ>/BRAND/MASCOT/` | маскот (только у Aura) |
| `<ПРОЕКТ>/BRAND/TEMPLATES/` | шаблоны каруселей, роликов, презентаций: где код и примеры |

Общие правила роликов для всех проектов (форматы, безопасная зона, звук, порядок работы, чек-лист) —
`CONTROL/VIDEO-RULES.md`. Ролики делаются в репозитории `Ostap-87/VIDEO-HUB`, готовые кладутся сюда в `VIDEO/`.

## 3. Как материал движется

```
TEXT + PHOTO / VIDEO   →   READY/ГГГГ-ММ-ДД_ЧЧММ_тема/   →   PUBLISHED/ГГГГ-ММ/ГГГГ-ММ-ДД_ЧЧММ_тема/
      (запас)               post.md + photo.jpg / video.mp4      + info.json (когда вышло, ссылка)
```

- **Имена:** `ГГГГ-ММ-ДД_тема.ext` в запасе, `ГГГГ-ММ-ДД_ЧЧММ_тема` (папка) в READY и PUBLISHED. Тема — латиницей
  через дефис (`unitree-g1`). Одна тема в разных сетях называется одинаково.
- **Папка поста** в READY:
  - `post.md` — текст поста (для STORIES может быть пустым);
  - `photo.jpg` — одно фото; в карусели и сторис — `01.jpg`, `02.jpg`, `03.mp4` … по порядку;
  - `video.mp4` — видео; `cover.jpg` — обложка видео (YouTube, Reels), если нужна;
  - `meta.yaml` — необязательно: заголовок (YouTube, статья Дзена), ссылка, хештеги, заметки.
- **В PUBLISHED** к папке поста добавляется `info.json`:
  `{"published_at": "2026-11-01T09:00:00+03:00", "url": "…", "post_id": "…", "published_by": "script | claude | chatgpt | user"}`.
- **Файлы не удаляются, только переносятся:** запас → READY → PUBLISHED.
- **Видео хранятся через Git LFS** (`.gitattributes`) и никогда не удаляются.

## 4. Обязательные правила контента

- **Контент уникальный:** у каждого проекта и в каждой сети свои тексты и фото. Один и тот же текст или фото
  не может лежать в двух сетях или повторять уже вышедшее — перед добавлением сверяйся с READY и PUBLISHED.
  Исключения утверждает пользователь, они записаны в правилах проекта; сейчас одно: Facebook и LinkedIn ostapdotcenko
  повторяют статью блога (`OSTAPDOTCENKO/RULES.md`).
- Правила применяются по старшинству: `<СЕТЬ>/RULES.md` → `<ПРОЕКТ>/RULES.md` (вместе с `BRAND/BRAND.md` и `VIDEO.md`)
  → этот файл. Для роликов: `<ПРОЕКТ>/VIDEO.md` → `CONTROL/VIDEO-RULES.md`.
- Перед работой над постом прочитай правила проекта и сети, перед картинкой — `BRAND/BRAND.md`, перед роликом — `VIDEO.md`
  и `CONTROL/VIDEO-RULES.md`.
- Решения пользователя в правилах помечены `[П]` и собраны в разделе «Решения пользователя» — они окончательные.
  Остальные пункты с пометкой «Черновик на согласовании» и «Открытые вопросы» окончательными не считаются,
  пока пользователь их не утвердил.
- Факты — только из материалов пользователя и сайтов проектов. Не придумываем.
- **Картинки Higgsfield — только после того, как пользователь увидел цену и согласился.**
- Ключи доступа — только в GitHub Secrets. Никогда не просить их в чат и не записывать в файлы.

## 5. Как работать с заданиями (чтобы другой агент мог продолжить)

1. Новые задания лежат в `CONTROL/TASKS/INBOX/` (файл на задание).
2. Берёшь задание — переносишь его в `IN-WORK/`, дописываешь в файл, кто взял и когда. **Сразу коммит и пуш.**
3. Работаешь мелкими шагами, после каждого шага — коммит и пуш. Незакоммиченная работа при сбое теряется.
4. Готово — переносишь в `DONE/` с итогом: что сделано, где лежит результат.
5. Каждое действие — строка в журнале дня `CONTROL/JOURNAL/ГГГГ-ММ-ДД.md`: время, агент, что сделано.

Новый агент после переключения читает `TASKS/IN-WORK/`, `JOURNAL/` за последние дни и продолжает с того места,
где остановился предыдущий.
