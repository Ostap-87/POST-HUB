# POST-HUB: правила автопубликации

Единое место для постов **GlobalTechTour** и **Aura Robotics** и их публикации по расписанию —
с **1 ноября 2026**: Telegram-каналы, Instagram, блоги сайтов, Facebook и LinkedIn (через Make).
Пиши пользователю по-русски. Все изменения — коммит и пуш в `main`.

## Связанные репозитории (не дублируем, а опираемся)

| Репозиторий | Что там | Что берём |
|---|---|---|
| `Ostap-87/SINOTECH` | сайт globaltechtour.ru; блог — массив `blog[]` в `src/data/site_content.example.json`; сервер (VPS) с эндпоинтом Telegram `scripts/content-publish.py` и генератором картинок `scripts/image_gen.py` | формат статьи блога, тон и чек-лист поста (`CLAUDE.md`) |
| `Ostap-87/AURA` | сайт и отдельный блог aura-robotics.ru | формат статьи блога Aura |
| `Ostap-87/MyFirst` | прежний инструмент: очереди Instagram `content/instagram/<бренд>/queue.json`, публикация через GitHub Actions, лимиты сетей (`remotion-video-tools/docs/`); картинки Telegram в `tg-images/` | код публикации в Instagram; **`tg-images/` не трогать** — на них ссылаются уже вышедшие посты |
| `Ostap-87/VIDEO-HUB` | ролики, презентации, стиль бренда, каталог картинок Higgsfield | стиль картинок, учёт `source-videos/higgsfield/использовано.json` |

**Один канал — один публикатор.** Когда канал переезжает сюда, его очередь в MyFirst и отправку
через другие сессии выключаем, иначе посты выйдут дважды. Что уже переехало — в `каналы.yaml` (поле `status`).

## Каналы

Реестр — `каналы.yaml`. Каждый канал: `id`, сеть, бренд, адрес, способ публикации, статус.
Блоги брендов разные: блог GTT — про рынок Китая, блог Aura — про роботов. Посты одного бренда
не уходят в каналы другого.

## Порядок контента (обязательно)

1. **Сначала статья в блоге, потом посты** в соцсетях со ссылкой на неё
   (`https://globaltechtour.ru/blog/<slug>` или блог Aura). Тему без статьи в блоге не публикуем.
2. В день публикации блог выходит первым, соцсети — после того как статья появилась на сайте.
   Если статья не вышла, соцсети этого поста не публикуются (ссылка вела бы в никуда).
3. Текст — по правилам SINOTECH `CLAUDE.md`: живой, статусный тон («продаём доступ и инсайты, а не тур»);
   первая строка ≤ 90–100 символов и закончена сама по себе (Дзен берёт её в заголовок);
   цифры и детали — со второго предложения; без отдельной рекламной строки в конце —
   ссылка на статью вшита в последнее смысловое предложение; факты о роботах не старше конца 2025 года.
4. Факты — только из статей пользователя и сайтов. Не придумываем.

```
  2026-11/

      пост.yaml                 дата, время, бренд, каналы, slug статьи, одобрено ли

      telegram.md               ≤ 1024 символа (подпись к фото), разметка HTML
      instagram.md              ≤ 2200 символов, ≤ 30 хештегов; ссылки не кликабельны → «ссылка в профиле»
      linkedin.md               ≤ 3000 символов
      facebook.md               если нет — берётся linkedin.md
      картинка-16x9.jpg         блог, Telegram, Facebook, LinkedIn (1600×900)
      картинка-4x5.jpg          Instagram (1080×1350)
      промпт.txt                запрос в Higgsfield — чтобы перегенерировать
      статус.json               пишет публикатор: где и когда вышло, id и ссылка

```

Пример — `посты/_пример/`. Папки с `_` в начале публикатор пропускает.

## Картинки (Higgsfield)

- **Новые генерации — только после показа цены и согласия пользователя.** Сначала проба на 3 статьях
  с точной ценой, потом партиями по неделе.
- Стиль GTT: реалистичное редакционное фото, Китай и технологии, акценты фирменного синего `#1a73e8`.
  Стиль Aura — по VIDEO-HUB `reels-studio/CLAUDE.md`, раздел «Второй бренд: Aura Robotics».
- **На картинке нет текста и чужих логотипов** (Higgsfield искажает надписи).
- Форматы: 16:9 и 4:5. Сохраняем JPG (качество 90, до ~1 МБ), имена — как в структуре выше.
- Одна картинка — один раз: сверяем с `картинки/использовано.json` и с VIDEO-HUB `source-videos/higgsfield/использовано.json`.
- Перед одобрением — лист картинок недели в чат.

## Публикация

- **Расписание — GitHub Actions** в этом репозитории. Работает само, не зависит от сессий Claude.
  Запуски — только в слоты из `каналы.yaml` (чтобы уложиться в бесплатные минуты GitHub);
  задержка в несколько минут возможна.
- Публикатор берёт пост, если: `approved: true`, время наступило, канала ещё нет в `статус.json`.
  Опоздание больше 6 часов — не публикуем автоматически, сообщаем пользователю.
- Порядок внутри поста: блог → Telegram → Instagram → Make (Facebook, LinkedIn).
- **Блог GTT:** коммит статьи в `blog[]` репозитория SINOTECH (уникальные `id`, `slug`, дата ISO).
  Сайт пересобирается сам через существующий вебхук деплоя. **Блог Aura:** аналогично в AURA (формат уточнить).
- **Telegram:** Bot API напрямую из GitHub Actions; подпись к фото ≤ 1024 символа, `parse_mode: HTML`.
- **Instagram:** Graph API, два шага: контейнер → публикация; картинка по публичной ссылке.
  Код — из MyFirst (`publish-instagram.mjs`).
- **Facebook и LinkedIn — через Make:** POST на вебхук сценария, JSON
  `{post_id, brand, text_facebook, text_linkedin, image_url, link}`. Сценарий публикует в страницу FB
  и в LinkedIn и отвечает модулем Webhook response с id постов — их записываем в `статус.json`.
- После каждого запуска — отчёт пользователю в Telegram: что вышло, что нет и почему.
- Ручной запуск и сухой прогон (`dry_run`) — кнопкой Run workflow.
- Пауза: `approved: false` у поста или отключить workflow в GitHub (Actions → Disable).

## Секреты

Только в GitHub: **Settings → Secrets and variables → Actions**. Никогда не просить ключи в чат
и не писать их в файлы репозитория.

| Секрет | Для чего |
|---|---|
| `TG_BOT_TOKEN` | бот, который публикует в каналы (админ в каждом канале) |
| `TG_REPORT_CHAT` | куда слать отчёты (личный чат пользователя с ботом) |
| `IG_TOKEN_GTT`, `IG_USER_GTT`, `IG_TOKEN_AURA`, `IG_USER_AURA` | Instagram (уже заведены в MyFirst — перенести) |
| `MAKE_WEBHOOK_URL` | вебхук сценария Make (FB + LinkedIn) |
| `SITE_REPO_TOKEN` | запись статей в SINOTECH и AURA (fine-grained токен только на эти два репозитория) |

Токен Instagram лучше от системного пользователя Meta Business — он не истекает; обычный живёт 60 дней.

## Как работает сессия Claude здесь

1. Статьи от пользователя → по папкам `посты/ГГГГ-ММ/ГГГГ-ММ-ДД-<slug>/`, `пост.yaml` с датой и каналами.
2. Версии текста под каналы — по лимитам и чек-листу выше. Статья блога не меняется по смыслу.
3. Картинки — после согласия на бюджет; лист недели в чат.
4. После «да» пользователя — `approved: true`, коммит и пуш.
5. Новая возможность или договорённость → в том же коммите обновить этот файл и README.
